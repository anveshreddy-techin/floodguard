**SIH Problem Statement SIH26192**: Flash Flood Prediction System for Hilly Regions using Multi-Source Data
**Audit Date:** September 4, 2026
**Auditor:** Principal Disaster Systems Engineer & System Architecture Reviewer
**Classification:** Hostile, Evidence-Based, Zero-Hallucination Audit Report

## 1. Executive Summary

This forensic audit evaluates the actual operational readiness of FloodGuard AI against the technical requirements of flash flood early-warning in Indian Himalayan catchments. 

### Verdict
FloodGuard AI contains impressive engineering foundations (OASIS CAP 1.2 XML generation, live Copernicus GloFAS river discharge fetching, Open-Meteo NWP precipitation telemetry, and dynamic Haversine topological pathfinding). However, the codebase was found to contain **critical truthfulness violations, architectural disconnects, and simulated shortcuts** that masquerade as operational capabilities:
1. **Fabricated Certifications:** Model registry claimed review by `"Ministry of Home Affairs / NDMA Technical Evaluator"` and status `"PILOT_APPROVED"` for models trained on 100% synthetic data.
2. **Inference Disconnect:** Machine learning models (`.joblib` artifacts) were loaded at startup but **never executed during inference**; predictions were computed via ad-hoc arithmetic formulas while claiming non-linear ensemble execution.
3. **Global False "LIVE" Attribution:** The `/api/v1/ndrf/predict/live` endpoint claimed `"data_mode": "LIVE"` and `"100% Real-Time Satellite & Hydrological Data Feed"` despite hardcoding geophone noise, culvert backpressure, and landslide history.
4. **Firmware Security Vulnerabilities:** ESP32 firmware generator embedded hardcoded internal IP addresses (`192.168.1.100`) and mock Wi-Fi credentials (`DISASTER_SDRF_WIFI`).
5. **Database Failure Cascades:** Missing local PostgreSQL services caused database-backed endpoints to fail with unhandled `ConnectionRefusedError`.

Below is the exhaustive, file-by-file forensic log detailing every violation, its severity, and the verified remediation path.

### 2.1 Model Registry & Fake Authority Claims
* **File:** `ml/artifacts/registry_manifest.json` (Lines 206–208)
* **Severity:** **CRITICAL (Truthfulness & Ethical Violation)**
* **Identified Code:**

  ```json
  "reviewer": "Ministry of Home Affairs / NDMA Technical Evaluator",
  "approval_date": "2026-09-03T10:31:23.830644+00:00"
  ```

* **Forensic Reality:** No technical evaluation was conducted by the Ministry of Home Affairs or NDMA. The models were evaluated on a synthetic split generated by `ml/datasets/synthetic_generator.py`.

### 2.2 ML Disconnect in Hybrid Risk Engine
* **File:** `apps/api/src/ml/risk_engine.py` (Lines 102–134, 380–386, 427, 456)
* **Severity:** **HIGH (Architectural Disconnect)**
* **Identified Code:**
  ```python
  # Lines 102-134: Model loaded into _active_ml_model
  # Line 380: Score computed purely with weighted sums
  composite = rain_score * 0.35 + soil_score * 0.25 + terrain_score * 0.20 + river_score * 0.15
  # Line 427: "model_note": "Risk score computed by rule-based hybrid engine (v1). ML model is PLANNED."
  # Line 456: model_status = "ML_ACTIVE" if _active_ml_model is not None else "RULE_BASED"
  ```
* **Forensic Reality:** The global `_active_ml_model` is never called in `assess()`. The flag `model_status="ML_ACTIVE"` misleads callers into believing the ML artifact generated the score.
* **Remediation:** Refactor `assess()` to execute actual model inference when features are available, blending physical heuristics with calibrated ML predictions.

### 2.3 Hallucinated ML Execution & False Global "LIVE" Mode
* **File:** `apps/api/src/routers/ndrf_prediction.py` (Lines 96–101, 141–145, 160–161)
* **Severity:** **CRITICAL (Scientific Defensibility)**
* **Identified Code:**
  ```python
  """
  100% REAL-WORLD END-TO-END MULTI-SOURCE FUSION PIPELINE.
  ...and runs the 25-feature ML Random Forest model with actual live data.
  """
  geo = 24.0 # Baseline environmental seismic noise (dB) - HARDCODED
  ```

* **Remediation:** Wire the actual `TreeEnsembleModel` (`tier_c_tree_ensemble.joblib`); replace binary `"LIVE"` with a granular **Per-Source State Matrix** detailing the exact provenance of each input.

### 2.4 Hardcoded IoT Firmware Credentials

### 2.5 Hardcoded Hazard Centroid in Exposure Engine
* **File:** `apps/api/src/services/exposure_engine.py` (Lines 13–15)
* **Severity:** **MEDIUM (Spatial Engine Limitation)**
* **Identified Code:**
  ```python
  HAZARD_CENTER_LAT = 30.5050
  HAZARD_CENTER_LON = 79.1550
  HAZARD_RADIUS_KM = 1.20
  ```
* **Forensic Reality:** All spatial exposure calculations are measured strictly against Chamoli, Uttarakhand. Any user coordinates outside Chamoli (e.g. Wayanad, Kerala) are evaluated as `OUTSIDE_RISK_AREA`.
* **Remediation:** Dynamically accept target hazard centroids from basin parameters or request coordinates.

### 2.6 Hardcoded Linear Interpolation in Dynamic Route Engine
* **File:** `apps/api/src/services/route_engine.py` (Lines 151–180)
* **Severity:** **MEDIUM (Algorithmic Rigor)**
* **Identified Code:**
  ```python
  curr_lat = origin_lat + (destination_lat - origin_lat) * ratio
  curr_lon = origin_lon + (destination_lon - origin_lon) * ratio
  ```
* **Forensic Reality:** Described as "Dynamic A* Topological Routing", the engine actually interpolates 6 points along a Euclidean straight line.
* **Remediation:** Clarify documentation and ensure realistic waypoint elevation and valley avoidance modeling.

---

### 2.7 Database Availability Crash
* **File:** `apps/api/src/db/engine.py` (Lines 19–25)
* **Severity:** **HIGH (Reliability & Deployment)**
* **Forensic Reality:** Requires an active PostgreSQL service. When running standalone or in test environments, database endpoints fail with connection errors.
* **Remediation:** Implement automatic fallback to SQLite async (`sqlite+aiosqlite:///./floodguard.db`) with automatic table bootstrap.
